# MVP – трекер тренировок

Монорепозиторий (pnpm + Turborepo). Полное ТЗ – в файле `ТЗ MVP – трекер тренировок (Android + iOS).md`.

```
apps/
  mobile/     Expo-приложение (React Native, Expo Router)
  api/        Hono-сервер
packages/
  domain/     бизнес-логика, общая для телефона и сервера
  schemas/    Zod-схемы запросов и ответов API
  db/         схема Drizzle для PostgreSQL и миграции
  content/    каталог упражнений (JSON)
```

## Запуск

Нужны Node.js 20.19.4+ (лучше 22) и pnpm (`corepack enable pnpm`).

```bash
pnpm install
pnpm dev:api      # API на http://localhost:3000
pnpm dev:mobile   # Expo: w – браузер, a – Android, QR – телефон
pnpm catalog:import   # один раз: загрузить каталог упражнений в API
```

- **База.** Без настроек API работает на PGlite – PostgreSQL внутри процесса, данные лежат в
  `apps/api/.data`. Для настоящего PostgreSQL: `docker compose up -d` и `DATABASE_URL` в
  `apps/api/.env` (пример – `apps/api/.env.example`). Миграции применяются при старте сервера.
- **Почта.** Пока не задан `SMTP_URL`, код для входа печатается в консоль сервера.
- **Адрес API для телефона** задаётся в `apps/mobile/.env.local` (пример – `apps/mobile/.env.example`).

## Деплой

Сервер для продакшена – `deploy/`: Docker Compose с API, PostgreSQL, HTTPS (Caddy) и ежедневными
бэкапами; инструкция в `deploy/README.md`. Сборки приложения – EAS, профили в `apps/mobile/eas.json`.

## Каталог упражнений

Каталог лежит в `packages/content/catalog`: оборудование, мышцы и упражнения на двух языках.
Приложение несёт его в себе, поэтому библиотека работает без сети; сервер раздаёт обновления
по номеру версии.

```bash
pnpm catalog:import   # загрузить каталог в запущенный API (версия растёт, если он изменился)
```

Для другого сервера – переменные `API_URL` и `ADMIN_TOKEN`.

Как добавить упражнение:

1. Допишите запись в один из файлов `catalog/exercises/*.json` без поля `id`
   (новый файл нужно подключить в `packages/content/src/index.ts`).
2. `pnpm --filter @mvp/content assign-ids` – проставит `id`. Он больше никогда не меняется.
3. `pnpm test` – проверит формат, ссылки на мышцы и оборудование, совпадения названий.
4. `pnpm catalog:import`.

## Программа по анкете и из текста

- **Анкета.** Шаблоны дней лежат в `packages/content/src/templates.ts`: день – список слотов,
  слот – список упражнений по убыванию предпочтения. Берётся первое, для которого в месте
  тренировок есть оборудование. Сплит, объём и подгонку под длительность считает
  `packages/domain/src/generation.ts`; то же самое отдаёт сервер в `POST /v1/programs/generate`.
- **Импорт из текста.** `packages/domain/src/import-text.ts` разбирает строки вида
  «Жим лёжа 3×8-10, отдых 2 мин» и сопоставляет названия с каталогом: точное совпадение,
  синонимы, затем похожее название. Работает на телефоне без сети; разбора через ИИ пока нет.

## Базы данных

- **Сервер** – PostgreSQL, схема в `packages/db/src/schema.ts`, миграции в `packages/db/drizzle`.
- **Телефон** – SQLite, схема в `packages/db/src/sqlite/schema.ts`, миграции в
  `packages/db/drizzle-sqlite`. Данные пользователя (места тренировок, программы, тренировки)
  создаются на телефоне и работают без сети.
- **Синхронизация.** Триггеры SQLite кладут каждую изменённую строку в очередь `outbox`;
  после входа в аккаунт очередь уходит на сервер (`POST /v1/sync/push`), а изменения с других
  устройств приходят через `GET /v1/sync/pull`. При конфликте побеждает более поздний
  `updated_at`. Сценарий «тренировка без сети → сеть» проверяет `apps/api/test/offline.test.ts`.

После изменения любой из схем – `pnpm db:generate`: команда создаёт миграции для обеих баз и
упаковывает миграции телефона в модуль, который попадает в сборку приложения.

`drizzle-orm` установлен только в `packages/db`. Остальные пакеты берут операторы запросов из
`@mvp/db` (сервер) и `@mvp/db/sqlite` (телефон): две копии `drizzle-orm` несовместимы по типам.

## Веб-версия

Веб-сборка нужна только для разработки – чтобы смотреть экраны в браузере. Для неё в проекте
есть две подпорки: заголовки изоляции в `apps/mobile/metro.config.js` (SQLite в браузере без
них не запускается) и патч `patches/expo-sqlite@57.0.3.patch` (исправляет в веб-версии
expo-sqlite обрезание ответов длиннее 255 байт). На Android и iOS они не влияют.
